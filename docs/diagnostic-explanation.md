# 本机诊断解释

在诊断页运行一次“诊断”后，会出现“诊断解释”卡片，给出中文或英文摘要、检测依据和建议的下一步。

## 规则与本机模型

规则解释立即可用，不依赖 Apple Intelligence。它只解释已取得的检测证据：

- 系统代理操作错误、缺失的核心监听器和已知进程占用。
- 系统 DNS 查询结果（不把系统解析失败直接定位为 Mihomo DNS 故障）。
- HTTP 响应、服务限流、未取得响应的探测，以及部分成功的探测。
- Nexora TUN 与检测到的系统隧道路由，明确区分已知状态和待确认的归属。

Apple 的 `SystemLanguageModel.default` 可用时，卡片显示“本机 AI 解释”按钮。按下后，模型仅选择和整理已有证据句子的重点；检测依据与下一步仍由规则确定，不允许模型编造新故障或修改任何网络设置。

本功能只使用系统本机模型；未接入 Private Cloud Compute 或其他云模型，不需要 API 密钥。模型不可用时显示具体原因，规则解释照常保留。

本次在这台 Mac 上检查到 `deviceNotEligible`，因此当前可直接使用规则解释，本机 AI 入口暂不可用。这是系统报告的可用状态，不代表更改某个 Nexora 设置即可启用。

## 输入与生命周期

模型只接收白名单布尔状态、枚举和统计计数，不接收 IP、域名、URL、配置名、节点名、订阅内容、原始错误或日志。模型调用由用户主动触发。

生成最多等待 20 秒，可随时取消。修改节点、模式、代理、TUN、配置或出口状态，会使旧诊断失效；上次解释会保留时间并明确标记为过期，供阅读参考。重新诊断、切换应用语言、退出应用也会取消旧生成；晚到的结果不会覆盖新状态。模型失败或输出不合法时保留规则解释并提示回退。

## 判断边界

HTTP 429 是检测服务限流，不直接代表全网断开；收到其他非成功 HTTP 状态也不能单独证明节点或订阅失效。未知监听进程不等于已证明端口冲突。发现 utun 路由并不能单独证明另一个 VPN 覆盖了 Nexora，自有 TUN 不应被误认作竞争 VPN。

解释是诊断时刻的快照，不代表所有网站、应用和后续时刻的状态。

参考：[Apple SystemLanguageModel](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel)。
